Key Concepts -- Understand
	1: Repository:
		>> Repo is used to store/save/keep development project
		>> It contains folders and any type of files like: HTML, TXT, CSS, JavaScript, Java, Images,... etc
	2: Branch:
		>> B is used to work with different version of the repository at the same time.
		>> By default GitHub has Master/Main branch --> (has the stable code)
		>> Any other branch is the copy of the master/main branch and that exists a certain time
		>> New Branches -- Bug fixes -- feature development -- Feature_CaroselAutomation
			SearchFieldBugFix
	3: Commits:
		>> At GitHub changes are called commits
		>> Each commit has a description/reason -- explain the change
			Example: "Carousel feature of the home page has been automated."
					"Search field bug fixes has been automated and added to the smoke test suite"
	4: PR -- MR (Merge Request -- GitLab)
		>> PR - Pull Request
		>> PRs are the heart of the GitHub Collaboration
		>> PRs proposes that your changes be merged to the main/master branch
		>> PRs shows the difference between your code and the original code
			Additions: + green color
			Subraction: - red color
	5: Conflict:
			when does the conflict happens?
				>> Merge conflicts happens when two developers make different changes to the same line of the same file
				>> M C happens when one developer edits a file and other dev deletes the same file
		

Difference between Git and GitHub 
	Git:
		:: Is a software
		:: Installation: on your machine/computer
		:: Command line
		:: Can work offline
	GitHub:
		:: Is a service
		:: Installation: Hosted on the cloud/web
		:: Provides GUI -- UI (Graphical User Interface)
		:: Cannot work offline
